# Compile-time routes and OpenAPI

`gen_routes.hpp` is generated by scanning headers under `IDHANServer/src` for
`Get`, `Post`, `Put`, `Patch`, `Delete`, and `Endpoint` annotations. It includes
those headers and captures a sorted, recursive reflection snapshot of
`idhan::httpapi`. Both native route registration and OpenAPI compilation use
that snapshot. There is no maintained endpoint or route-group list.

Adding, editing, or removing route headers updates the generated include file
through CMake dependencies. The scanner ignores comments and literal contents;
it does not parse handler bodies or infer schemas. Annotated declarations and
request/response types belong in headers. Handlers can be inline in those headers
or implemented in `.cpp` files. `/health` is a header-only example.

## Document and endpoint

The compiler creates the complete OpenAPI JSON with `consteval` reflection. Its
final bytes reside in an immutable array. `GET /openapi.json` is public and wraps
that array in an IOBuf without copying or serializing it. There is no document
generation at server startup or request time, and generation requires no database.
The API viewer at `/api` reads this endpoint. The generated document is the API
reference; there is no separate handwritten specification or static YAML endpoint.

Export the OpenAPI JSON without running IDHAN or PostgreSQL:

```sh
cmake --build build/debug --target IDHANOpenAPI -j"$(nproc)"
```

Every server or `IDHANOpenAPI` build overwrites the repository-root
`openapi.json` with a formatted snapshot of the compiled specification. Include
changes to this file in API commits so the current reference is readable on
GitHub. Unchanged content leaves the file untouched; clean builds do not delete
the snapshot. The build never stages or commits it.

The tracked snapshot is only an output. Compilation, the server endpoint, and
the binary export never read it. Python 3 formats it with sorted keys, two-space
indentation, and a final newline; formatting it cannot change the compiled API.

Optionally validate the exported document:

```sh
python -m pip install -r tools/openapi/requirements.txt
python tools/openapi/validate.py --input build/debug/IDHANServer/generated/openapi.json
```

The artifact is `build/debug/IDHANServer/generated/openapi.json`, and the include
header is beside it as `gen_routes.hpp`. The export step copies the compiled
binary's document section using objcopy. It never executes the server or generates
schemas. This also works when cross-compiling with a compatible objcopy tool.
Route discovery and export use CMake scripts in `IDHANServer/cmake`; Python 3
formats the tracked snapshot and runs the optional validator. Schema edits require a rebuild
and restart of the server or container because the document is embedded in the binary.
Use the validator's `--offline` option to check local references, examples, and
route coverage without downloading the official OpenAPI schema.

## Schema conventions

Typed requests generate parameter and JSON schemas, including nested arrays,
maps, variants, field-name aliases, integer ranges, minimum and maximum
constraints, and recursive component references. `std::optional<T>` input
fields accept absence and `null`; `http::possiblyMissing<T>` accepts absence
and delegates present values to `T`.
Default-initialized fields allow absence. Empty `std::optional<T>` response fields
are emitted as `null`; empty `http::possiblyMissing<T>` response fields are omitted.
OpenAPI marks only the latter as omittable; nesting the two allows both states.
Input and output components are kept distinct.

`JsonResponse<T, Status>`, `EmptyResponse<Status>`, and response variants describe
status codes and response bodies. Unknown fields remain allowed, matching the
runtime warning policy. Untagged variants use `anyOf`. Duplicate paths/methods,
operation IDs, or incompatible component definitions fail constant evaluation.

Authentication uses the same header names and build configuration as the server.
`Public` clears the operation's security requirements. An auth-disabled build
produces an auth-disabled contract. UI/static and Hydrus compatibility routes
remain outside the native API document.

## Descriptive and custom metadata

Use `Summary{"..."}`, `Description{"..."}`, and `OperationId{"..."}` on functions.
`Group{"Tags"}` places an operation in a documentation group through OpenAPI
`tags`; multiple annotations support multiple groups without a manual registry.
These annotations store their text as constexpr object values, and can also be
declared as reusable `inline constexpr` objects. `SchemaName{"..."}` on a DTO
supplies its public component name.
`Input<Body>{"media/type", Required}` describes a request body, independently of
`Parameters<QuerySchema>` for query parameters. `Output<Body>{Status, "media/type"}`
describes a response. Input and output default to `JsonDocument` and
`application/json`; output status defaults to 200 and input bodies are required
by default. Omit `Input` for bodyless endpoints. Use `Output<void>{204}` for an
empty response. Multiple output annotations support alternative statuses and
media types, including files and streams, without changing handler parsing.
`OpenAPISchema<T>::schema(SchemaDirection)` can provide a constexpr JSON schema
for a custom codec representation.

Context-based input schemas are marked with `x-idhan-custom-parser`. Their opaque
fields remain unconstrained. Raw `Response` handlers receive a default response
entry alongside explicit `Output` declarations because the compiler cannot infer
their runtime status branches or bodies. JSON successes are declared separately
from the shared `application/json` error responses (`{"error":"message"}`). Authored handwritten API files are
retained during migration to typed DTOs.

`Validation<Rule>{"name"}` validates a URL placeholder against a premade
`validation::Integer<T>`, `validation::PositiveInteger<T>`, or `validation::UUID`
rule. Its required path parameter schema includes the matching integer bounds,
positivity, or UUID format, rather than assuming every context-based path value
is a string. Unknown placeholder names fail document compilation and route setup.
